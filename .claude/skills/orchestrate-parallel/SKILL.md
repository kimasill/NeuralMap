## 역할

- **조율자(메인 세션)**: 작업을 **충돌 없는 슬라이스**로 나누고, 독립된 조각마다 `parallel-research` / `parallel-implement` / `parallel-verify`를 **동시에** 띄운다.
- **서브에이전트**: 각자 컨텍스트가 분리되므로, 메인에는 **요약·결정·통합**만 남긴다.

## 절차

1. **슬라이스**: 디렉터리·모듈·이슈 단위로 나누고, 같은 파일을 두 트랙이 건드리지 않게 한다.
2. **병렬 스폰**: 독립 조사는 `parallel-research`, 독립 구현은 `parallel-implement`, 검증은 `parallel-verify`를 병렬로 호출한다.
3. **통합**: 결과가 돌아오면 충돌·중복·누락을 메인에서 정리하고, 필요 시 한 번 더 좁은 범위로 재스폰한다.
4. **피하기**: 한 파일에 대한 순차 의존 편집은 병렬이 아니라 단일 트랙으로 처리한다.

## Agent teams (선택)

여러 **세션**이 서로 메시지까지 주고받아야 하면 Agent teams를 고려한다. 실험 플래그는 `.claude/settings.json`의 `env`에 있을 수 있다.

## 스킬과 토큰 (동작 요약)

- **메인 세션**: 스킬 본문이 항상 통째로 들어가는 것이 아니라, 기본적으로는 **이름 + 설명(메타)** 가 올라가고 실제 호출 시 `SKILL.md` 본문이 로드된다.
- **서브에이전트**: 부모 대화의 스킬을 **상속하지 않는다**. 필요한 경우 서브에이전트 정의 YAML의 `skills:` 로 **프리로드**한다.
- **과다 프리로드 금지**: 병렬 워커마다 긴 스킬을 여러 개 넣지 말고, 꼭 필요한 소수만 넣는다.
